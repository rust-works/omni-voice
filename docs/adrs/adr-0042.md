# ADR-0042: Native Apple-Silicon ASR Backend Selection

## Status

✅ Accepted (2026-06-18) — depends on [ADR-0041](adr-0041.md) (Apple Silicon as
the sole platform); redefines the backend tiering of [ADR-0040](adr-0040.md);
adopts Metal/Accelerate for the candle runtime of [ADR-0033](adr-0033.md).

## Context

[ADR-0041](adr-0041.md) narrows omni-voice to Apple Silicon macOS and drops the
cross-platform / pure-Rust / no-C++ / Windows constraints. Those constraints
were the *only* reason [ADR-0040](adr-0040.md) settled for candle Whisper +
LocalAgreement-2, whose ~2.4 s partial latency is **architectural** — Whisper is
not streaming-native (no causal encoder, no streaming KV-cache), so no amount of
hardware makes it sub-second.

With the constraints gone, the streaming-native models the project already
benchmarked are on the table:

| Model            | WER          | First-partial latency | Runtime          |
|------------------|--------------|-----------------------|------------------|
| Voxtral Realtime | 2.84–3.15 %  | 0.64–0.91 s           | MLX (Python)     |
| moonshine-v2     | competitive  | sub-second            | MLX (Python)     |
| parakeet-mlx     | competitive  | sub-second            | MLX (Python)     |
| candle-streaming | 9.2 %        | ~2.41 s (structural)  | pure Rust (CPU)  |

The current selector is the three-arm `match` in `src/voice/factory.rs`
(`mock`, `whisper-candle`, `whisper-candle-streaming`). candle is CPU-only
(`Device::Cpu` at `src/voice/backends/candle.rs:79`; `default-features = false`).

Two decisions are recorded here: **(1)** which streaming backend is the v1
low-latency direction, and **(2)** Apple-Silicon hardware acceleration of the
existing candle backends.

## Decision

### 1. v1 low-latency direction: streaming-native MLX (subprocess)

The headline streaming tier is a **streaming-native MLX model run as a
supervised subprocess** — Voxtral Realtime, moonshine-v2, or parakeet-mlx. This
is the direct path to the sub-second interactive UX the rescope exists to
deliver. We accept the trade-offs [ADR-0041](adr-0041.md) made admissible:

- a **Python + MLX runtime dependency** (install story owned by
  `install-model` / a `doctor`-style check);
- **cold-start** (~5 s) mitigated by pre-warming the subprocess;
- **subprocess supervision** (spawn, health, restart) on the host process.

The specific model is selected in **Phase 3** by spiking moonshine-v2
(simplest), Voxtral (best quality), and parakeet-mlx on the committed 5-minute
fixture, then productizing the winner. This ADR records the *shape* (subprocess
MLX, streaming-native) so Phase 3 starts from a settled direction; it does not
pre-commit the exact model.

### 2. candle-streaming is demoted to the pure-Rust baseline

`whisper-candle-streaming` ([ADR-0040](adr-0040.md)) **stays in the tree** as
the pure-Rust, dependency-free baseline that builds today and needs no Python.
It is no longer the headline streaming tier, and its "lowest-common-denominator
for Windows" rationale is void under [ADR-0041](adr-0041.md). It remains a valid
fallback when the MLX runtime is unavailable.

### 3. candle runs on Metal

The existing candle batch (`whisper-candle`) and streaming
(`whisper-candle-streaming`) backends move off CPU-only onto Metal:

- enable candle's `"metal"` (and optionally `"accelerate"`) feature on
  `candle-core` / `candle-nn` / `candle-transformers`;
- replace `Device::Cpu` at `src/voice/backends/candle.rs` with
  `Device::new_metal(0)`. Every Apple Silicon Mac (the only supported target,
  [ADR-0041](adr-0041.md)) has a Metal-capable GPU, so Metal is assumed present;
  device creation surfaces a clear error if it is somehow unavailable rather
  than silently degrading to the ~4.5× slower CPU path. There is **no
  device-level CPU fallback** — that branch would be dead code on Apple Silicon.

Both backends load the same `WhisperEngine::load()`
(`src/voice/backends/candle_streaming.rs` reuses `src/voice/backends/candle.rs`),
so the single device site covers both. **Metal op coverage for the
candle-transformers Whisper graph must be measured, not assumed** — some ops can
silently fall back to CPU on Metal — and RTF benchmarked before/after on the
5-minute fixture.

**Measured (2026-06-18, this change).** On the committed 5-minute fixture, the
unpaced streaming envelope runs at **RTF 0.075 on Metal** (wall 22.6 s / 300 s
audio) versus the ADR-0040 CPU baseline of **RTF 0.34** — a ~4.5× throughput
gain — at **WER 9.35 %** (unchanged from the CPU baseline's 9.2 %, confirming the
Metal graph is numerically correct, not degraded by silent CPU-fallback ops). The
batch model-gated test also passes on Metal. Latency remains architectural and
unchanged (Metal buys throughput/keep-up headroom, not interactivity — which is
precisely why the headline tier is the streaming-native MLX backend).

### 4. Resulting backend tiering

| Tier                  | Backend                         | Latency class            | Runtime           |
|-----------------------|---------------------------------|--------------------------|-------------------|
| Low-latency (headline)| streaming-native MLX (Phase 3)  | sub-second interactive   | MLX (Python)      |
| Pure-Rust baseline    | `whisper-candle-streaming`      | bounded ~1.5–3 s lag     | candle + Metal    |
| Batch                 | `whisper-candle`                | n/a (batch)              | candle + Metal    |
| Test                  | `mock`                          | n/a                      | none              |

## Consequences

### Positive

- The product gets sub-second interactive transcription — the rescope's purpose.
- Metal acceleration benefits the existing candle backends immediately,
  independent of the Phase-3 work.
- A clear fallback ladder: MLX low-latency → candle pure-Rust → mock.

### Negative

- The headline tier introduces a Python/MLX runtime dependency and subprocess
  lifecycle management — new install, doctor, and supervision surface.
- Cold-start latency needs pre-warming to not undercut the latency win.
- Metal op-coverage gaps may cap the candle acceleration below expectations
  until measured.

### Neutral

- candle-streaming's code is unchanged by the demotion; only its documented role
  shifts.
- The voxtral.c native-C+Metal FFI path remains a *future* Python-free option
  (would require relaxing `unsafe_code = "deny"`); the candle-Voxtral pure-Rust
  port becomes low-priority, its only edge (cross-platform) having evaporated.

## Out of Scope (Tracked Elsewhere)

- Selecting and productizing the specific MLX model (spike + supervision +
  pre-warm + install/doctor UX) — Phase 3 of the rescope epic.
- The platform commitment and build guard — [ADR-0041](adr-0041.md).

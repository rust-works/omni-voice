# ADR-0041: Apple Silicon macOS as the Sole Supported Platform

## Status

✅ Accepted (2026-06-18) — supersedes the cross-platform stance in
[ADR-0035](adr-0035.md), [ADR-0037](adr-0037.md), and [ADR-0040](adr-0040.md);
amends the pure-Rust / no-C++ rationale of [ADR-0033](adr-0033.md) and
[ADR-0034](adr-0034.md); leaves [ADR-0031](adr-0031.md) /
[ADR-0032](adr-0032.md) (audio traits) untouched. The backend-selection
consequences are recorded in [ADR-0042](adr-0042.md).

## Context

omni-voice has, until now, carried four overlapping platform constraints —
**cross-platform**, **pure-Rust**, **no-C++/CMake**, and **must-work-on-Windows**.
They were never load-bearing for the product; they were load-bearing for the
*ASR backend*, and they are precisely what made low-latency streaming
intractable.

[ADR-0040](adr-0040.md) is the clearest statement of the cost: candle Whisper +
LocalAgreement-2 was chosen as the **lowest-common-denominator (LCD) streaming
floor** — "the only streaming option on Windows" — and its ~2.4 s partial
latency was documented as **structural, not tunable** (the encoder always runs a
zero-padded 30 s mel with no streaming KV-cache). The cross-platform / Windows
constraint forced the floor; the floor forced the latency.

The decisive observation is that the cross-platform streaming machinery
**mostly does not exist in code yet**:

- The OS-gated backend-descriptor registry + `voice doctor`
  ([ADR-0035](adr-0035.md)) and the pure-C native FFI backends
  ([ADR-0037](adr-0037.md)) are **accepted-but-unimplemented ADR designs**.
- The real backend selector is a three-arm `match` in
  `src/voice/factory.rs` (`mock`, `whisper-candle`, `whisper-candle-streaming`).
- candle runs **CPU-only** (`Device::Cpu` hardcoded at
  `src/voice/backends/candle.rs:79`; `default-features = false` on
  `candle-core`/`-nn`/`-transformers`).
- There are **zero `target_arch` gates** anywhere — the project genuinely
  builds everywhere today, but nothing depends on it doing so.

The upstream extraction already anticipated narrowing: voice was moved into
omni-voice *because* it "has a distinct platform-support matrix." This ADR
exercises that latitude. **This rescope is omni-voice-only** — omni-dev has no
voice code or open voice issues.

## Decision

**omni-voice targets Apple Silicon macOS (`aarch64-apple-darwin`) as its sole
supported platform.** Concretely: `target_os = "macos"` and
`target_arch = "aarch64"`.

### 1. Hard build guard

A `compile_error!` gates the crate to Apple Silicon — the honest form of
"only runs on Apple Silicon", failing fast at compile time with a clear
message rather than producing a binary we do not support:

```rust
#[cfg(not(all(target_os = "macos", target_arch = "aarch64")))]
compile_error!("omni-voice supports only Apple Silicon macOS (aarch64-apple-darwin).");
```

It lives at the top of `src/lib.rs`; the binary (`src/main.rs`) depends on the
library crate, so guarding the library covers both.

### 2. CI, release, and packaging narrow to one target

- CI (`.github/workflows/ci.yml`) runs on `macos-latest`; ALSA install steps go.
- Release (`.github/workflows/release.yml`) builds only `aarch64-apple-darwin`;
  the Linux and Windows matrix arms and the Windows-zip branch go.
- `.github/workflows/voice-streaming-keepup.yml` is **deleted** — its sole
  purpose was validating the streaming lag envelope on Linux + Windows runners,
  which evaporates.
- `flake.nix` narrows to `aarch64-darwin`; the Linux/ALSA branch goes.

### 3. The four constraints, reframed

| Constraint            | Before                                  | After                                                |
|-----------------------|-----------------------------------------|------------------------------------------------------|
| Cross-platform        | Hard requirement                        | **Dropped** — single target                          |
| must-work-on-Windows  | Hard requirement (drove the LCD floor)  | **Dropped**                                          |
| pure-Rust             | Load-bearing rationale                  | **Optional** — a means, not a goal (see ADR-0042)    |
| no-C++/CMake          | Load-bearing rationale                  | **Optional** — Apple-native C/Metal/Python permitted |

Apple-Silicon C/Metal/Accelerate and subprocess (Python/MLX) backends are now
admissible. The pure-Rust path is kept where it is the simplest option, not
because portability demands it.

### 4. What this supersedes or amends

- **[ADR-0035](adr-0035.md) (OS-gated registry) — superseded.** "OS-gated" is
  moot with a single OS/arch. A backend registry may still be useful for
  *model-presence* availability (`voice doctor`), but its OS/arch-gating premise
  is gone; any future registry is re-derived under this ADR, not ADR-0035.
- **[ADR-0037](adr-0037.md) (pure-C FFI on non-Windows) — superseded.** "Non-Windows"
  collapses to "Apple Silicon", and [ADR-0042](adr-0042.md) chooses a *subprocess*
  MLX backend over in-process C FFI for v1. The voxtral.c FFI option survives
  only as a future Python-free candidate, re-scoped under ADR-0042.
- **[ADR-0040](adr-0040.md) (candle LCD streaming floor) — superseded.** The
  "universal floor, including Windows" framing is gone. The candle-streaming
  *algorithm* and backend remain in the tree, demoted to the pure-Rust baseline
  per [ADR-0042](adr-0042.md); they are no longer the headline streaming tier.
- **[ADR-0033](adr-0033.md) / [ADR-0034](adr-0034.md) — amended, not replaced.**
  `candle` (batch ASR) and `tract-onnx` (speaker embedding) remain the runtimes.
  Only their *pure-Rust justification* becomes optional. ADR-0033's runtime
  choice now additionally adopts Metal/Accelerate (ADR-0042).
- **[ADR-0031](adr-0031.md) / [ADR-0032](adr-0032.md) — untouched.** cpal's
  `!Send` macOS `Stream` is now the baseline, not a portability burden; the
  audio-trait seams are unaffected.

## Consequences

### Positive

- The streaming-native, sub-second Apple-Silicon models the project already
  benchmarked (Voxtral Realtime, moonshine-v2, parakeet-mlx) become viable —
  the rescope's whole purpose (see [ADR-0042](adr-0042.md)).
- Metal/Accelerate acceleration of the existing candle backends is unblocked.
- The ~30 `#[cfg(unix)]` / `#[cfg(not(unix))]` / `#[cfg(target_os = "linux")]`
  branches (32 `cfg(unix)` across `claude_cli.rs`/`model_config.rs`/`test_support.rs`,
  plus the two `not(unix)` / `linux` sites) collapse; `nix` becomes an
  unconditional dependency.
- CI is simpler and faster (one runner, no ALSA, no cross-OS lag-envelope job).

### Negative

- Linux and Windows users lose support outright; the `compile_error!` is a hard
  stop, not a degraded experience. This is intentional and irreversible without
  a follow-up ADR.
- Contributors on non-Apple-Silicon hardware cannot build or run the project.
- The pure-Rust portability invariant — a genuine engineering asset — is
  surrendered. Re-acquiring it later (e.g. for a Linux port) means re-walking
  the ADR-0040 trade-offs.

### Neutral

- No `target_arch` gating existed before, so there is no platform abstraction
  layer to unwind — the change is narrowing config and deleting dead branches,
  not refactoring.
- The candle batch and streaming backends keep working unchanged on the
  supported target; only their strategic role (ADR-0040 → ADR-0042) shifts.

## Out of Scope (Tracked Elsewhere)

- The native Apple-Silicon ASR backend selection and Metal/Accelerate adoption —
  [ADR-0042](adr-0042.md).
- Productizing the chosen streaming-native backend (subprocess supervision,
  pre-warm, model install/doctor UX) — Phase 3 of the rescope epic.
- The full open-issue triage (close-moot / defer / promote) — the rescope epic.

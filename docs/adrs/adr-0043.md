# ADR-0043: Voxtral-MLX as the Default ASR Backend

## Status

✅ Accepted (2026-06-25) — revises the default-backend stance of
[ADR-0033](adr-0033.md) (mock-until-release-cycle) and the off-by-default
feature decision of [ADR-0039](adr-0039.md); aligns the shipped default with the
headline tier of [ADR-0042](adr-0042.md).

## Context

[ADR-0042](adr-0042.md) names `voxtral-mlx` (in-process MLX via `mlx-rs`,
[ADR-0039](adr-0039.md)) the headline streaming-native ASR tier, and #27
validated it on-host: streaming first-`Partial` **1.26 s**, streaming WER
**4.6 %**, batch WER **4.0 %** at RTF **0.193–0.263**. But the *shipped* default
did not match that decision:

- The `voxtral-mlx` Cargo feature is **off-by-default** ([ADR-0039](adr-0039.md)),
  so a default build does not contain the backend.
- The factory's default backend is **`mock`** ([ADR-0033](adr-0033.md): "remains
  `mock` until the model storage convention has been through at least one release
  cycle").

[ADR-0039](adr-0039.md) made the feature off-by-default primarily to keep the
`mlx-rs` C++/CMake build out of **non-Apple builds** (it originated in omni-dev's
cross-platform context). Under [ADR-0041](adr-0041.md), omni-voice targets
**Apple Silicon macOS only** — there are no non-Apple builds to protect, so that
half of the rationale is moot. What remains is the cost of requiring a CMake +
C++ toolchain (and a multi-minute MLX compile) on *every* build.

## Decision

`voxtral-mlx` becomes the default ASR backend, at both layers:

1. **Default feature.** `default = ["voxtral-mlx"]` in `Cargo.toml`, so the
   shipped binary contains the backend. The feature gate is *retained* (not made
   unconditional) so a lighter build remains available via
   `--no-default-features`.
2. **Default backend selection.** `create_default_transcriber` defaults to
   `"voxtral-mlx"` when the feature is compiled, falling back to `"mock"` under
   `--no-default-features` — so the light build still has a working,
   dependency-free default.

**Accepted cost: a CMake + C++ toolchain is now required for all default
builds** — `cargo build`, `cargo install omni-voice`, CI, and contributor
checkouts. This is acceptable because omni-voice is Apple-Silicon-only (every
supported target has the toolchain readily available) and `voxtral-mlx` is the
validated, headline experience the product exists to deliver.

## Consequences

### Positive

- The out-of-the-box experience is the real, sub-second streaming ASR backend,
  not a stub — the shipped default now matches [ADR-0042](adr-0042.md)'s headline
  tier.
- `voice listen` (#8) and other live flows get a sensible default backend with no
  per-command special-casing.
- The `--no-default-features` escape hatch preserves a fast, toolchain-light
  build that defaults to `mock`.

### Negative

- **CMake + C++ required for every default build** — `cargo install omni-voice`
  and contributor builds now need the toolchain; default CI jobs build `mlx-rs`
  (a multi-minute compile) each run. Mitigated: Apple-Silicon-only ⇒ the
  toolchain is standard, and `--no-default-features` stays available.
- **First-run model download.** With the runtime default now `voxtral-mlx`, a
  fresh `voice transcribe` / `voice listen` with no model errors with an install
  hint (a ~3 GB INT4 download). The clear error stands today; the
  confirm/auto-download UX is tracked in #14 (and download integrity in #29) and
  should land alongside or soon after.

### Neutral

- The `voxtral-mlx` feature is retained (default-on, not unconditional), so the
  `cfg(not(feature = "voxtral-mlx"))` path and the `mock` fallback remain compiled
  and correct.
- [ADR-0039](adr-0039.md)'s C++/CMake relaxation is unchanged in substance; only
  its *default* status flips. [ADR-0033](adr-0033.md)'s `mock` backend remains the
  `--no-default-features` default.

## Out of Scope (Tracked Elsewhere)

- First-download confirmation / auto-download UX — #14; download integrity — #29.
- The `voice listen` realtime scheduler that consumes the default backend — #8.
